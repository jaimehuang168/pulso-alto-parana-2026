Cómo recorrer este manual

Personal de campo: comience en la página 14 y use la Guía rápida de dos páginas. No necesita instalar Git, Node.js ni Supabase en el teléfono.

Administrador técnico: siga las páginas 4–13 en orden. Cada etapa termina con una comprobación antes de continuar.

Viewer: lea las páginas 14 y 18. Debe recibir una cuenta propia y autorización; conocer el enlace no otorga acceso.

Paso 1 · Preparar la computadora

Use una computadora propia o administrada por su organización. Los encuestadores no realizan este paso.

  1. Descargue el ZIP con manuales ES y pulse Extraer todo. No ejecute los archivos desde dentro del ZIP.
  2. Abra la carpeta interior Pulso_Alto_Parana_v2. Debe ver web, supabase, scripts, docs, tests y README.md.
  3. Instale Git desde git-scm.com, GitHub CLI desde cli.github.com, Node.js LTS desde nodejs.org y PowerShell 7 desde Microsoft. Los enlaces oficiales están en las páginas de fuentes.
  4. Cierre y vuelva a abrir la terminal. Seleccione PowerShell 7, no Windows PowerShell 5.1. Cambie a la carpeta del proyecto; adapte la ruta siguiente a su extracción.
Set-Location "C:\Pulso\Pulso_Alto_Parana_v2"
$PSVersionTable.PSVersion
git --version
gh --version
node --version
npx --version
Test-Path .\supabase\00_INSTALL_NEW_PROJECT.sql

El último comando debe mostrar True; los demás deben mostrar versiones sin errores. La CLI Supabase se ejecutará con npx; no es necesario instalar Python, Docker ni una base local para la ruta remota con --use-api.

GitHub: iniciar sesión una sola vez

gh auth login --web --git-protocol https --scopes repo,workflow
gh auth setup-git --hostname github.com
gh api user --jq .login
Autorice únicamente en el navegador oficial. No envíe tokens, contraseñas ni claves secretas por chat. Compruebe que el usuario mostrado sea el propietario previsto del repositorio.

Instalación y comandos: [R1], [R8], [R9], [R19], [R20], [R21].

Pulso v2 · 05 / 24

Paso 2 · Crear la base en Supabase

  1. Entre en el Dashboard de Supabase con su cuenta. Cree un New project en la organización correcta.
  2. Primero use un proyecto separado de entrenamiento, por ejemplo pulso-ensayo-2026. Elija región, plan y contraseña de base según sus necesidades; revise costos y respaldos antes de confirmar.
  3. Espere a que el proyecto esté disponible. Anote el Project Reference y obtenga la Project URL y la publishable key desde Connect o Settings → API Keys.
  4. Abra SQL Editor → New query. Abra en su computadora supabase/00_INSTALL_NEW_PROJECT.sql como texto, copie su contenido completo y ejecútelo en ese proyecto nuevo.
  5. No ejecute adicionalmente 001 y 002: el instalador integrado ya incluye ambas migraciones. Si hay un error, deténgase y conserve el mensaje; no desactive las reglas de seguridad para continuar.

Comprobar la instalación, en SQL Editor

select state, fieldwork_date, viewer_enabled
from public.settings where id = 1;

select count(*) as ciudades from public.districts;
select count(*) as candidatos
from public.candidates where active;
select count(*) as capturas from public.responses;

Se espera: setup, fecha 2026-10-04, Viewer false, 4 ciudades, 12 candidatos y 0 capturas. Un resultado distinto requiere revisión.

Project Reference es el identificador del proyecto, no la contraseña de la base. La clave publicable empieza con sb_publishable_. Una clave sb_secret_ o service_role nunca va al navegador ni al repositorio.

Claves y Dashboard: [R4]. Estructura y comprobaciones: supabase/00_INSTALL_NEW_PROJECT.sql del proyecto.

Pulso v2 · 06 / 24

Paso 3 · Crear el primer administrador

  1. En Supabase abra Authentication → Users → Add user / Create new user. Cree una cuenta con un correo real bajo control de la coordinación y una contraseña fuerte.
  2. Confirme ese usuario mediante el flujo administrativo disponible. No habilite registro público para resolver una cuenta sin confirmar.
  3. En Authentication → Sign In / Providers o configuración general, mantenga habilitado el acceso con email y contraseña, desactive Allow new users to sign up y desactive Allow anonymous sign-ins. El nombre exacto del menú puede variar.
  4. Copie el contenido de supabase/02_bootstrap_admin.sql al SQL Editor. Sustituya allí REPLACE_WITH_COORDINATOR_EMAIL por el correo recién creado y ejecute el SQL. Conserve el marcador en el archivo fuente para no publicar su correo al subir el proyecto.
  5. Verifique el perfil con la consulta siguiente. No vuelva a ejecutar el bootstrap sobre un perfil existente ni cree un disparador que haga administrador a toda persona registrada.
select code, role, active
from public.profiles
where code = 'COORD-01';

Debe existir una fila con COORD-01 / admin / true. Esto acredita la creación del perfil, no una prueba completa de permisos.

Primer acceso: escriba el correo real del administrador, no COORD-01. Las cuentas posteriores creadas por la aplicación usan códigos como CDE-01 o VIEW-001.

Custodia de la cuenta

No comparta esta cuenta con los 60 encuestadores. Cada persona necesita su propio usuario. La contraseña de la cuenta, la contraseña de la base y la clave secreta Supabase son tres datos distintos.

Configuración de Auth: [R5]. Bootstrap: supabase/02_bootstrap_admin.sql.

Paso 4 · Publicar la función de cuentas

La función provision-team crea cuentas y restablece claves. Sin ella la web puede mostrar el inicio de sesión, pero no podrá preparar al equipo.

  1. En Settings → API Keys, obtenga o cree una clave secreta del proyecto para el backend. No la copie al proyecto de código.
  2. En Edge Functions → Secrets, cree los dos valores indicados en la tabla. El origen corresponde al GitHub autenticado en el paso 1.
  3. Desde la carpeta del proyecto ejecute los comandos. Sustituya el texto de ejemplo por el Project Reference, sin incluir https:// ni .supabase.co. Autorice la CLI de Supabase en el flujo que le muestre.
  4. Abra Edge Functions y compruebe que aparece provision-team desplegada. La prueba funcional se hará al crear las cuentas en el paso 8.
Nombre del secretValor
APP_ORIGINhttps://SU_USUARIO.github.io
Solo esquema y dominio; sin /repositorio/ ni barra final.
PULSO_SUPABASE_SECRET_KEYClave sb_secret_… de este mismo proyecto. Nunca publicarla.
npx supabase --version
npx supabase login
$ProjectRef = "REEMPLAZAR_POR_PROJECT_REF"
npx supabase functions deploy provision-team --project-ref $ProjectRef --use-api

La ruta --use-api solicita el empaquetado remoto y evita necesitar Docker. Se pasa --project-ref explícitamente; para esta ruta no es necesario ejecutar supabase init ni sobrescribir el config.toml ya incluido.

Mantenga [functions.provision-team] verify_jwt = false como viene en el proyecto: la función valida el token de usuario y el perfil admin dentro del código. No quite esa validación ni interprete la opción como autorización pública. Debe probarse el rechazo a no administradores.

CLI, despliegue y secrets: [R1], [R2], [R3]. Implementación: supabase/functions/provision-team/index.ts.

Pulso v2 · 08 / 24

Paso 5 · Publicar el sitio en GitHub

Este paso publica código fuente público y la página de acceso. Las respuestas no se guardan en GitHub. No use el asistente si su organización requiere un repositorio privado sin revisar primero su plan y procedimiento.

  1. Compruebe que la carpeta no contiene CSV de contraseñas, entrevistas, coordenadas operativas, tokens ni archivos de respaldo. Conserve esos datos fuera de la carpeta del proyecto.
  2. Desde una copia nueva extraída, ejecute el asistente. Para entrenamiento use un nombre diferente del sitio de producción.
  3. Cuando solicite Supabase project URL, pegue la URL del proyecto; cuando solicite PUBLISHABLE key, pegue solo la clave sb_publishable_… de ese mismo proyecto.
  4. Lea el usuario y nombre del repositorio propuesto. Confirme escribiendo exactamente el nombre solicitado. La creación de un repositorio público requiere esta autorización explícita.
  5. Espere a que finalice Deploy Pulso frontend. El enlace solo está confirmado cuando el workflow termina correctamente y GitHub devuelve la URL.
.\scripts\Deploy-GitHub.ps1 -RepoName "pulso-ensayo-2026"

Para producción, repita desde otra copia limpia y con una base nueva, usando -RepoName "pulso-alto-parana-2026". No reutilice a ciegas una carpeta que ya tiene .git ni intente borrar un repositorio existente para repetir.

El asistente no instala Supabase. Si se interrumpe después de subir el código, no lo ejecute de nuevo desde el inicio: compruebe el repositorio y continúe desde la página 9.

Si Windows bloquea el script

Revise primero su contenido y el mensaje. Para un archivo confiable bloqueado por procedencia, use Unblock-File .\scripts\Deploy-GitHub.ps1. Si la política lo requiere y su organización lo permite, use Set-ExecutionPolicy -Scope Process RemoteSigned. No desactive el antivirus ni eluda una política corporativa.

GitHub Pages y repositorios: [R6], [R12]. Política de PowerShell: [R17].

Pulso v2 · 09 / 24

Paso 6 · Confirmar el enlace y recuperar fallos

  1. En el repositorio abra Settings → Secrets and variables → Actions → Variables. Deben existir SUPABASE_URL y SUPABASE_PUBLISHABLE_KEY; confirme que son del mismo proyecto.
  2. Abra Settings → Pages → Build and deployment → Source y seleccione GitHub Actions. No seleccione /docs ni intente servir todo el proyecto como una página HTML.
  3. En Actions → Deploy Pulso frontend → Run workflow, elija main y ejecútelo. Abra la ejecución: build y deploy deben terminar en verde.
  4. Copie el enlace de Settings → Pages o del entorno github-pages. Ábralo primero en la computadora y luego en un teléfono.
  5. En Supabase Authentication → URL Configuration, configure Site URL con ese enlace completo. Si habilita posteriormente redirecciones de Auth, autorice solo destinos que controle.
  6. Vuelva a comprobar APP_ORIGIN: es únicamente el origen HTTPS del enlace, sin la ruta del repositorio. Inicie sesión con el correo real del primer administrador.

Pulso v2 · 10 / 24

Paso 7 · Cargar los locales reales

  1. Entre como administrador y abra Administración → Candidaturas y locales.
  2. Seleccione una ciudad. Compare sus candidatos y Lista con el registro oficial y corrija lo que corresponda antes de abrir el operativo.
  3. Sustituya los locales NO OFICIAL. Para cada local complete Código del local, Nombre oficial, Dirección y Punto de encuesta autorizado. No basta con quitar el texto “práctica” de un nombre inventado.
  4. Use Añadir local para los puntos adicionales y Quitar solo para locales sin personal asignado. Si un local ya tiene cuentas, reasígnelas antes de quitarlo.
  5. Latitud y longitud del local son opcionales: complete ambas o deje ambas vacías. Son coordenadas del local, no una ubicación tomada del elector.
  6. Pulse Guardar catálogo de esta ciudad. Repita el proceso para las cuatro ciudades. No cambie de ciudad con cambios aún sin guardar.
CampoCriterio de carga
CódigoIdentificador operativo único y reconocible; por ejemplo, CDE-L01. El ejemplo no certifica un local.
Nombre y direcciónTranscribir de la información oficial y comprobar la ubicación.
Punto autorizadoDescribir el punto asignado por coordinación, con las autorizaciones necesarias.
CoordenadasUsar valores verificados o dejar vacíos; no inventar coordenadas.
La v2 admite entre 1 y 200 locales por ciudad, pero solo 15 puestos de encuestador por ciudad. Un local sin personal no tiene cobertura por el solo hecho de figurar en el catálogo. La aplicación no administra automáticamente cambios de turno o itinerarios.

Los catálogos y las asignaciones se bloquean al abrir la recepción. Defina la distribución definitiva antes del operativo; no planifique cambiar a un encuestador de local a mitad de la jornada con esta versión.

Pulso v2 · 11 / 24

Paso 8 · Crear y asignar las cuentas

  1. En Administración, pulse Crear 60 encuestadores. En Equipo el botón equivalente dice Crear 60 cuentas. Espere sin cerrar la ventana.
  2. Pulse Guardar credenciales privadas. Guarde el CSV en una carpeta privada fuera del repositorio. Verifique el número de cuentas creadas y cualquier error; no suponga que una operación interrumpida creó las 60.
  3. En Equipo, revise cada código, agregue el nombre del encuestador y use Asignar local → Guardar asignación. La distribución inicial es automática entre locales activos, no su plan de campo definitivo.
  4. Verifique operativamente 15 cuentas activas y correctamente asignadas por ciudad. El simple conteo de puestos del servidor no sustituye esta revisión.
  5. Entregue a cada persona únicamente su código, su contraseña, su local, su punto, su turno, el enlace correcto y el contacto de coordinación. No comparta el CSV completo en un grupo.
  6. Pida que cada usuario entre y use Guía → Cambiar mi contraseña; el administrador dispone del mismo botón en Administración. La nueva contraseña debe tener al menos 12 caracteres.

Viewer y administradores adicionales

Pulse Crear viewer / administrador. Ejemplos de códigos válidos: VIEW-001 y ADMIN-002. Elija el rol y, para Viewer, una ciudad o todas. Un administrador siempre tiene acceso completo. Guarde la credencial resultante antes de cerrar.

Las claves iniciales se muestran una sola vez, pero no son contraseñas que expiran automáticamente después del primer uso. El cambio inicial no se fuerza en esta v2; coordinación debe comprobarlo. Las cuentas por código usan correos técnicos no entregables: la recuperación normal es Restablecer clave, no un correo de “olvidé mi contraseña”.

La interfaz permite activar/desactivar encuestadores y viewers. La baja de un administrador requiere al responsable técnico; no hay un botón equivalente de desactivación de admin en esta v2.

Pulso v2 · 12 / 24

Paso 9 · Ensayar y abrir la recepción

Preparar un ensayo sin mezclarlo con producción

  1. En el proyecto de entrenamiento, abra Administración → Jornada y protocolo. Use un nombre que identifique el ENSAYO y configure Fecha electoral con el día de la prueba.
  2. Documente el criterio de selección, locales, turnos, manejo de rechazos y contingencias. Seleccionar cada N.º elector debe reflejar un protocolo aprobado, no un número elegido para favorecer respuestas.
  3. Complete los locales y las 60 cuentas del entrenamiento. Compruebe la configuración y guarde la jornada. La casilla de verificación es una declaración del responsable; no debe marcarse falsamente.
  4. En la fecha de ensayo, pulse Abrir recepción. Realice solamente casos sintéticos. No recopile preferencias reales antes de la votación para “probar” la app.
La cabecera visual de esta v2 conserva “04 OCTUBRE 2026” incluso al cambiar la fecha de entrenamiento. Distinga el ensayo por su URL y proyecto separados; no use esa cabecera como comprobación de la fecha efectiva.

Pasar a producción

  1. Cree una base de producción nueva y un sitio separado; repita la instalación, función, administrador y cuentas. Mantenga 2026-10-04 en la configuración definitiva y compruebe 0 capturas.
  2. Verifique oficialmente cargo, fecha, candidatos y locales; apruebe el protocolo y pulse Guardar jornada. Confirme en los 60 teléfonos el enlace y local correctos.
  3. El 4 de octubre, a la hora interna autorizada y en horario de Asunción, pulse Abrir recepción. No altere la fecha de producción ni el reloj del teléfono para eludir el control.

La transición normal es Preparación → Recepción abierta → Recepción cerrada. No hay reapertura normal ni botón de volver a preparación. Abrir bloquea catálogos y asignaciones.

Pulso v2 · 14 / 24

Teléfono · Ingreso y preparación

  1. Reciba de coordinación el enlace HTTPS, su usuario y su contraseña individual. Un encuestador no necesita una cuenta GitHub o Supabase.
  2. En Android abra el enlace en Chrome; en iPhone ábralo en Safari. Evite el navegador integrado de WhatsApp y no use navegación privada.
  3. Inicie sesión conectado a Internet. Encuestadores: use el código asignado, por ejemplo MGA-01. Primer administrador: use su correo real. Viewer: use su código VIEW-….
  4. Antes de trabajar confirme su código, ciudad, local y punto. Si son incorrectos, avise y no registre entrevistas bajo una asignación ajena.
  5. Use Cambiar mi contraseña, compruebe batería y datos móviles, configure fecha y hora automáticas y conserve siempre el mismo navegador/dispositivo durante el turno.

Añadir un acceso en la pantalla de inicio

Android / Chrome: menú de tres puntos → opción de instalar o crear acceso directo → confirmar. iPhone / Safari: Compartir → Agregar a pantalla de inicio → Agregar; active Abrir como app web si aparece. Los nombres pueden variar por versión. [R15, R16]

Instalar un icono no prueba el modo sin conexión. Hágalo antes del turno, entre desde ese icono y ensaye allí. El navegador y la app instalada pueden no compartir la misma sesión o almacenamiento: nunca cambie de uno a otro con pendientes.

Comprobación de apertura

El encuestador debe ver Nueva encuesta y su local. Si aparece “La jornada está cerrada o en preparación”, espere a coordinación. No cambie la fecha ni solicite una cuenta admin para registrar.

Conserve fuera de la app el contacto de coordinación y el procedimiento ante falta de conexión. No anote contraseñas en este manual público.

Encuestador · Registrar una entrevista

  1. Acérquese únicamente según el protocolo aprobado. Confirme verbalmente que la persona ya votó y marque esa casilla solo si lo confirma. No pida documento ni comprobante de voto.
  2. Explique: “Buen día. Hacemos una encuesta anónima y voluntaria. Puede negarse o no revelar su voto. ¿Desea participar?” Si acepta, marque la casilla de consentimiento.
  3. Pregunte: “¿Por qué candidatura votó para la Intendencia Municipal?” Registre lo declarado, sin sugerir una opción ni comentar resultados.
  4. Toque la candidatura correspondiente. Si declara blanco o nulo, use esa opción. Si acepta la entrevista pero no revela el voto, use No revela su voto.
  5. Si rechaza participar, seleccione Rechaza la encuesta: no guarde una preferencia ni marque consentimiento. La confirmación de voto previo sigue siendo necesaria.
  6. Revise la opción elegida y pulse Guardar encuesta una vez. Espere el mensaje y compruebe Mi actividad. La siguiente entrevista debe comenzar con las casillas y selección nuevamente revisadas.
Si la persona no confirma que votó, este formulario no permite registrarla como entrevista válida. No invente confirmación ni convierta ese caso automáticamente en un rechazo. Siga el protocolo de elegibilidad de coordinación.
SituaciónRegistro correcto
Acepta y nombra candidatoCandidatura declarada; consentimiento sí.
Acepta, no desea revelarNo revela su voto; consentimiento sí.
No acepta la encuestaRechaza la encuesta; sin preferencia y consentimiento no.

Recibidas significa confirmadas por el servidor. Pendientes en este teléfono significa que aún falta confirmación; esas filas no aparecen todavía en el panel central.

Pulso v2 · 16 / 24

Encuestador · GPS, pendientes y errores

Ubicación del encuestador

El local y el punto asignados se guardan siempre. Para GPS pulse Obtener mi ubicación y autorice al navegador. Se registra una lectura puntual con hora y precisión; no se rastrea al elector ni hay seguimiento continuo. Si se deniega o falla, use Sin GPS y siga el protocolo. El GPS web exige contexto seguro y permiso. [R14]

Cuando se pierde Internet

  1. Continúe solo si el modo offline fue validado en su dispositivo y la app permite guardar. Las filas quedarán en Pendientes; el coordinador no conoce esa cantidad desde el panel.
  2. No borre historial/datos, no desinstale, no use incógnito y no cambie de teléfono, navegador, cuenta o proyecto para intentar resolver la cola.
  3. Al recuperar Internet, abra la misma app con la misma cuenta y pulse Pendientes → Sincronizar ahora. Compruebe que la cola queda en cero y aumentan las recibidas.
  4. Si una fila muestra error, anote el mensaje y avise. Use Reintentar después de corregir la causa. No vuelva a capturar la misma entrevista con un ID nuevo.

Corregir una equivocación

Si el servidor ya recibió la entrevista: Registro → Anular. El encuestador solo puede anular sus propias filas durante los 10 minutos siguientes a la recepción. La fila se conserva para trazabilidad y deja de contarse; fuera del plazo debe intervenir un administrador.

Descartar pendiente elimina la copia local y no equivale a anular una recepción ya confirmada. No lo use para “destrabar” un error de sincronización. Si hubo respuesta de red ambigua, coordinación debe verificar primero si el servidor ya recibió esa captura.

Antes de terminar el turno informe recibidas, pendientes e incidencias. La sincronización con la app cerrada no está garantizada. Un GPS antiguo no se presenta como ubicación actual.

Revisar un local o una persona

  1. Abra Locales para comprobar dirección, punto, cantidades y personal asignado. Los locales sin entrevistas deben investigarse, no ocultarse del informe.
  2. Abra Equipo y filtre ciudad/local o busque un código. Compare cantidad, última encuesta y última recepción. Es posible que la última recepción sea posterior por una cola offline.

El filtro por local cambia el conjunto contado. Antes de exportar o comunicar una cifra, confirme ciudad, local, base, fecha y última recepción.

Pulso v2 · 18 / 24

Viewer · Consulta y autorización

  1. El administrador crea una cuenta Viewer y elige alcance: una ciudad o todas. Un filtro de local dentro de esa ciudad no equivale a un permiso independiente por local.
  2. El usuario recibe su código y contraseña propios, abre el enlace correcto e ingresa. No debe recibir las credenciales de un administrador.
  3. Mientras Viewer esté bloqueado, verá Acceso a resultados pendiente. Esto no se corrige cambiando la clave; debe resolverlo coordinación.
  4. Solo después de verificar la autorización de consulta y las restricciones aplicables, el administrador usa Habilitar viewers. La aplicación no determina por sí misma el horario legal.
  5. Viewer consulta Resultados y Locales, elige el filtro permitido y lee la base y fecha de actualización. No puede capturar, exportar, administrar cuentas ni obtener entrevistas individuales o GPS de personal.

Al bloquear nuevamente

Bloquear viewers impide nuevas consultas autorizadas por ese permiso, pero no elimina capturas de pantalla o información que alguien ya vio. La revocación no debe tratarse como un mecanismo para retirar información difundida.

El artículo 306 del Código Electoral publicado por BACN prohíbe difundir resultados de boca de urna hasta una hora después del horario señalado para cerrar las mesas. Verifique la normativa aplicable y el horario oficial para este operativo. Un usuario privado, CSV o captura no constituye por sí solo una autorización de difusión. [R10]

Mantenga Viewer bloqueado hasta la decisión documentada del responsable. No anuncie un horario automático en esta v2. La revisión legal y las autorizaciones de campo corresponden a la organización.

Cierre, exportación y conservación

  1. Avise a los 60 encuestadores que detengan nuevas entrevistas conforme al plan. Pida a cada uno su cantidad recibida, pendiente e incidencias.
  2. Procure sincronizar antes del cierre. En Administración → Jornada y protocolo, pulse Cerrar recepción únicamente cuando corresponda y registre la hora.
  3. La v2 admite pendientes elegibles capturados antes del cierre hasta 24 horas después de la hora de cierre de la app. Deben cumplir fecha electoral, cuenta, local y demás validaciones. No autoriza entrevistas nuevas ni modifica el cierre oficial de mesas.

  5. Exporte los agregados y, si está autorizado, el detalle. Guarde copias en el almacenamiento privado de la organización, no en GitHub ni en grupos abiertos.

Actualizar el frontend ya publicado

No use nuevamente el asistente de creación para actualizar un repositorio existente. Revise el estado y los cambios, pruebe primero en entrenamiento y publique desde el repositorio local correcto.

Espere el workflow verde y compruebe el sitio. Un cambio en supabase/functions/provision-team exige volver a desplegar esa función. Un cambio en SQL requiere una migración planificada y respaldo: no vuelva a ejecutar el instalador de proyecto nuevo sobre producción.

Cuándo actualizar

Congele la versión antes del operativo. No fuerce recargas, cambios de URL, proyecto o limpieza de caché en teléfonos con pendientes. Valide el ciclo de actualización de la app instalada en entrenamiento antes de usar una versión nueva.

En macOS

Los pasos de navegador en Supabase y GitHub son los mismos. Instale Git, GitHub CLI y Node.js desde fuentes oficiales. npx supabase login y el despliegue con --project-ref funcionan desde Terminal en la carpeta del proyecto.

Deploy-GitHub.ps1 es un script PowerShell: no lo ejecute directamente con zsh. Puede usar PowerShell 7 para macOS instalado según Microsoft y ejecutarlo con pwsh, o pedir al responsable técnico que siga el flujo GitHub manual. La guía principal fue preparada para Windows.

No instale las herramientas técnicas en los teléfonos del equipo. Cada encuestador solo necesita el navegador/app instalada, Internet y su cuenta.

GitHub workflow: [R6]. CLI y despliegue remoto: [R1], [R2].
