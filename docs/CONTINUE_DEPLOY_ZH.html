使用既有 GitHub 專案，接續發布

程式與部署說明：繁體中文｜App 與調查員手冊：西班牙文

不要重建 repository。
目標是 jaimehuang168/pulso-alto-parana-2026。這份指南改用單一 ZIP 匯入。程式匯入、網站發布與正式多人驗收是三個不同檢查點。下列勾選進度只保存在閱讀裝置，不會更新 GitHub 或 Supabase。

第 1 步：上傳完整 ZIP，不必解壓縮

下載 Pulso_v2_Deploy_ZH_ES.zip，保留原檔名與內容。不要重新壓縮，不要上傳舊版 ZIP，也不要將它改成 .html。

開啟 GitHub 專案首頁，依序按 Add file → Upload files。把 ZIP 拖入畫面，填寫提交說明「匯入 Pulso 完整程式」，選擇提交到 main，按 Commit changes。若帳號規則要求 Pull Request，請依規則合併到 main，不要停用保護。

第 2 步：確認自動匯入結果

開啟 Actions，點 Import Pulso package。它會先檢查 ZIP 的 SHA-256、必要檔案與路徑，再匯入完整原始碼、執行測試並正常提交，不使用 force push。

成功後回到 Code，應看到 web、supabase、scripts、tests 與 docs。若顯示雜湊不符、缺少檔案或既有檔案不同，請保留錯誤，不要刪除 repository 或改掉檢查規則。

若匯入程序顯示 GitHub Actions 沒有寫入權限，先由 repository 管理者核對 Settings → Actions → General → Workflow permissions；只針對本專案確認允許此匯入工作流程寫入原始碼，遵守組織限制。不要開放其他無關服務或把 token 寫入程式。

第 3 步：完成 Supabase 後端

已有專用 Supabase 專案時沿用該專案，不要因為重新看指南而再建一次。尚未建立時，先建立獨立演練專案；正式資料庫與演練資料分開。以下安裝 SQL 只適用於全新專用資料庫。

Supabase Dashboard → 專案 → SQL Editor，執行 supabase/00_INSTALL_NEW_PROJECT.sql。Authentication → Users 建立自己的管理者帳號。停用公眾自行註冊及匿名登入。在 SQL Editor 貼上 supabase/02_bootstrap_admin.sql，只在 Editor 內替換管理者信箱占位文字，再執行。部署 supabase/functions/provision-team/index.ts，設定下列伺服器 Secrets。

Edge Function Secrets：

APP_ORIGIN=https://jaimehuang168.github.io
PULSO_SUPABASE_SECRET_KEY=只在SupabaseSecrets填入真正的SecretKey

APP_ORIGIN 不加 repository 子路徑，也不加最後斜線。Secret key 只能留在伺服器，不放入 GitHub variables、ZIP、前端或聊天。verify_jwt=false 不是開放權限；程式內仍須驗證 token 與資料庫中的 active admin，不可刪除。

使用本機 Supabase CLI 時，在解壓縮後的完整專案資料夾執行：

npx supabase login
npx supabase functions deploy provision-team --project-ref 你的PROJECT_REF --use-api

上述指令要在自己的終端機中完成帳號授權。若你尚未安裝 Node.js 或不熟悉 Edge Functions，可先完成第 1、2 步，不必為了上傳 ZIP 先安裝所有工具。

第 4 步：填入兩個公開連線設定

在 Supabase 的 Connect 或 API Keys 畫面取得同一個專案的 Project URL 與 Publishable key。

開啟 GitHub Actions Variables 設定，按 New repository variable，新增：

NameValue
SUPABASE_URL以 https:// 開頭的專案網址，格式為 https://專案代碼.supabase.co
SUPABASE_PUBLISHABLE_KEY以 sb_publishable_ 開頭的完整公開金鑰
不是 sb_secret_，不是 service_role，不是資料庫密碼。兩個公開連線值本身不提供管理者權限；真正權限仍由登入與後端規則決定。

第 5 步：啟用 GitHub Pages 並發布

開啟 Settings → Pages，在 Source 選 GitHub Actions。再到 Actions → Deploy Pulso frontend → Run workflow，選 main 並執行。

build 通過但 deploy 被跳過，不代表網站已上線。只有 deploy 成功，才從 Pages 設定或 deployment 摘要複製實際網址。本指南不提供尚未經發布驗證的預測 App 網址。

取得網址後，回 Supabase → Authentication → URL Configuration，把 Site URL 設為完整 App 網址（包括 repository 路徑）。這和只填網域來源的 APP_ORIGIN 不同。

第 6 步：帳號、投票所與手機驗收

管理者登入後，在 Administración 核對候選人、填入真正投票所地址與授權調查點，再建立 60 位調查員並逐一確認配置。每位人員只拿自己的帳密；不要公開整份 CSV。Viewer 預設關閉。

演練至少包含：兩支手機分別登錄、中央數量對帳、離線待傳後重開保留、補傳不重算、誤登撤銷、停用帳號生效、Viewer／調查員越權被拒，以及 60 帳號併發及集中回補。前端測試通過不能取代這些項目。

終端機方式：可選，不是 ZIP 上傳的前提

原始碼已匯入，且電腦已具備 Node.js 與 GitHub CLI 時，在完整專案資料夾執行：

node scripts/continue-deploy-zh.mjs --check
node scripts/continue-deploy-zh.mjs --publish

第一行唯讀檢查；第二行要求你在本機確認後才設定 GitHub 連線與 Pages。它不建立新 repository，不會自動改連另一個資料庫，不要求後端 Secret key。
