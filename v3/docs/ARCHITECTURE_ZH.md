# V3 架構與反向審查重點

## 不變條件

一個人可以有很多歷史任務，但同時最多一個 active 任務；舊任务可 draining。問卷綁原 task/person/point/questionnaire/grant，不能跟隨現行派任改變。已發布候選人及原始答卷 payload 不可原位改寫。數量只計 accepted，pending_review/excluded 分開。原收件回條 UUID 穩定。

前端 UI 篩選只避免操作混淆，不作為授權依據。每個 public.v3 RPC 驗證真實 auth.uid、Auth session_id、私有 actors.active 及任務／範圍。匿名使用者不能讀 App 資料。Edge 單次加入碼入口使用雜湊領用權杖、指定領用者、短期限、分開提交的限速計數；資料庫服務函式不授權 authenticated 執行。

## 模組

- migrations 004：私有資料模型、保留 V2 身分與 UUID、預設 RLS。
- 005：帶版本及冪等鍵的管理命令、所有收件／統計／匯入／匯出 RPC。
- 006：Auth建帳與本機DB無法同交易時的saga狀態、唯一加入碼領用、工作階段撤銷。
- 007：部署前檢查與明確切換；不直接開收、不假設可無損回到V2。
- 008：Storage附件、裝置回報、本人補傳復原、本人結束任務。
- field-enrollment：伺服器 Auth API；不把 Secret key、永久密碼放進QR或前端。
- core/api/views/app：純資料規則、雲端適配、角色畫面、控制器。
- vault：PBKDF2 + AES-GCM，每使用者／環境獨立加密；非可擷取金鑰只存記憶體。
- importer：只讀原始資料；限制ZIP大小、拒絕宏、外部連結、所有Excel公式、未核定的同名覆盖。

## 保守選擇與限制

1. 完全離線不支援新身分向中央取權；可用主管熱點，或核定紙本。
2. 工作階段重建後的舊資料，需本人結束原任務並明確申請補傳復原；一律待審。手機時間不能證明是在撤銷前訪問。
3. 共用裝置資料以不同密語加密。新使用者無法查看上一人的待傳；上一人需自己的帳号和密語解鎖。重設帳號密碼不會解密本機。
4. 本機回條保留到保存政策處理，不自動刪掉答卷。錯誤回應不算伺服器已收件。
5. Viewer採人工發布城市快照、小樣本／小格抑制。它不是差分隱私，也不是法律發布許可。
6. 問卷版本更新會暫停涉及的点、結束舊任务，不偷偷重绘正在作答的名單。已收舊版答案保留舊版統計。
7. 投票所已實際使用後名稱／位置不原位修改。需要新點及任務；正式行政更正另留事故紀錄，不能由Excel直接改历史。
8. 匯入可追加不同批次、容忍未使用空列；不自動合併同名人員。姓名不能作唯一身份。
9. Backup欄位是維護者簽認，不是備份引擎。保留政策文字不自動刪除個資或附件。
10. 60、120是測試負載，不是正式雲端方案的SLA。共用熱點大量加入／登入仍須按正式Auth速率限制驗收。

## 已在開發反查發現並修正的類型

- SQL變數遮蔽欄位导致工作階段撤銷選錯ID：加入反向測試，使用限定表別名。
- 原始答卷不可變觸發器誤取其他表欄位：分開處理答卷和問卷。
- 同一UUID不同內容的重送：拒絕覆蓋；同一內容回原回條。
- 只關閉V2 RPC不足：一併關閉舊表授權和既有建帳函式的服務路徑。
- 已登入但被停用的身分：伺服器每次查 active；重新啟用不復活舊工作階段。
- 同一人新登入無法處理原任務待傳：本人補傳復原且一律待審，不改原任務。
- Auth sessions 外鍵阻止登出清理：歷史補傳標記不使用限制刪除的 sessions 外鍵。
- browser測試部分失敗卻回傳成功：任何流程例外必定寫失敗並以非零結束。
- 匯出只載入首段：伺服器凍結快照、分頁讀完整，超過限制明確失敗不默默截斷。
